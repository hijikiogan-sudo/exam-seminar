# 更新手順

## 初回設定

GitHubリポジトリのSettings → Pages → Build and deployment → Sourceを**GitHub Actions**にします。`main`へのpushまたはActionsの「Run workflow」で、検証・PDF・ZIP生成と公開が動きます。クラウドが正本なので、別端末やCodexのクラウド環境から同じリポジトリを取得して作業できます。

## 動画を受け取ったら

既存のGoogle Drive `資料庫 / 02_成績 / 受験資料 / 入試実戦オンラインゼミ / 2026 / 実施日`を確認します。既存フォルダ・資料・共有設定を変更せず、その回を特定します。保存先のIDはNotion学習索引または接続の検索から取得し、公開リポジトリへ記載しません。

```bash
python3 scripts/new-session.py 2026-10-10
```

`private/drafts/2026-10-10`に6科目ファイルと`session.json`ができます。この下書きはGit除外です。教科の順序は国語・英語・社会・数学・理科。数学は要点整理と実践問題詳細に分けます。

## 解析と原稿の完成

[分析テンプレート](../templates/ANALYSIS.md)に沿って講義境界、要点、根拠、判別できない箇所を整理します。動画を確認していない場合は、確認したと書きません。補足例題にはその旨を表示します。数値・条件・解答・図の対応を点検します。

HTML断片にCSS、JavaScript、外部画像、個人情報、私的なURLを埋め込みません。`section`、見出し、表、SVG、`details/summary`などを使えます。IDは教科名を先頭につけ、同じ文書内で重複しないようにします。教科ごとの単元名と出典・不明点を`session.json`へ記入します。

内容、個人情報、数学2版の違いを確認してから登録します。

```bash
python3 scripts/review-session.py private/drafts/2026-10-10 \
  --confirm-content --confirm-privacy --confirm-math-variants
```

この確認は、人または作業中のCodexが実際に行います。フラグを付けるだけで内容が正しくなるわけではありません。未完成原稿・確認問題なし・危険なHTML・検出した個人情報候補・同一の数学2版は拒否します。既存日付の上書きも拒否します。

## 生成と保存

READMEのビルドコマンドを実行し、375px・768px・1440pxの画面とPDFの日本語・ページ切れを確認します。既存の出力先は上書きしません。

Driveにはその回の以下の完成物を保存します。

- 5教科まとめHTML（`_site/sessions/YYYY-MM-DD.html`）
- 科目別6種類（ZIP内の`科目別/`に完成HTMLを収録）
- 印刷用PDF（`_site/pdf/YYYY-MM-DD.pdf`）
- 一式ZIP（`_site/downloads/YYYY-MM-DD.zip`）

既存ファイルがあれば`サイト版_v2`などの新しい名前にします。削除・上書きは確認が必要です。アップロード後にDriveのファイル名、MIME、サイズ、親フォルダを読み戻し、可能ならPDFのページ数も確認します。

## GitHubとNotion

公開原稿とコードだけをコミットします。`private/`、元動画、認証情報を含めません。`main`へpushするとActionsが再生成し、検証成功後に公開します。公開URLとPDFを実際に開き、HTTP成功と内容を確認します。Actionsの成功だけで公開確認としません。

既存Notion学習索引の「実施済み」に日付・5教科のテーマ・Driveフォルダを追加し、公開ページとPDFのリンクも追記します。索引には全文教材を重複保存しません。既存の行を置換せず、追加または必要箇所だけ更新します。

順序は `動画アップロード → 5教科解析 → 科目別HTML → 5教科まとめHTML → 印刷PDF → Google Drive保存 → 閲覧サイト更新 → Notion索引更新` です。接続や保存が失敗した場合は、成功した工程と残った工程を区別して報告します。

## クラウド自動化の範囲

GitHub Actionsで自動化するのはビルド・PDF生成・ZIP作成・操作検証・Pages公開です。Drive保存・Notion索引更新は既存の接続でCodexが実行します。自動で動画を巡回する監視や、未確認教材の自動公開は設定していません。新しい回は動画を渡して依頼すると、同じ手順で追加できます。

## 失敗時と復旧

- ハッシュ不一致：原稿の差分を点検し、必要な修正について確認後、再レビューして`session.json`のハッシュを更新する。
- PDF生成・画面検証の失敗：Actionsログを確認し、修正を新コミットで追加する。既存公開は継続する。
- 公開後に誤りを発見：誤りと修正案を提示し、既存回の変更確認を得てから修正する。履歴は残す。
- 過去版に戻す必要がある場合：Git履歴から戻すコミットを作成する。履歴の削除やforce-pushは行わない。
- 非公開情報が紛れた場合：公開停止・履歴対処が必要なのでユーザーに対象と操作を示して確認する。
